## 〇、参照系：MMPV-RNA 的两级过滤（02b 粗筛 + 09b 精验）

MMPV-RNA 有**两个**过滤点，严格度不同，本模块需同时覆盖：

| | **L1 · 02b_Filter** | **L2 · 09b_Analysis_Verify** |
|---|---|---|
| 脚本 | `filter_virus.py` | `validate_rescue_cdd.py` |
| 时机 | 早期，contig 刚产出 | 后期，rescue 延伸 / HQ 序列精验 |
| 问题 | 哪些 contig 值得往下做？ | 这条**像不像它声称的那个属**？ |
| 判据 | CDD tier + 宿主归属 | CDD tier **+ 属/科核心域交叉验证** |
| 严格度 | 松（保留 ambiguous / unclassified） | 严（无属核心域 → 降为弱证据） |
| 输出 | viral / ambiguous / non_viral | 6 级 EVIDENCE |
| 目的 | 从海量 contig 保留候选 | 从候选里**去除假病毒** |

### L1 = 02b_Filter

`D:\桌面\延伸基因组\MMPV-RNA\virome_discovery_pipeline\filter_virus.py`
（流程位置 `virome_pipeline.py:11`：`02a_Identification → 02b_Filter → 03a_COBRA`）

**02b 原始设计**（`filter_virus.py` 文件头）：

```
UniProt: Diamond BLASTX + virus TaxID + keyword rescue
CDD:     mmseqs translated search + 3-tier classification
  -m filter   → viral + viral_plant + viral_bacteria
  -m strict   → viral only
  -m raw      → symlink only
```

### v2 最重要的修正：这是「过滤器」，不是「裁决器」

v1 规划写的是"判定四档：确认 / 疑似 / 存疑 / **排除**"——**这个思路是错的**。

02b 的核心哲学是**在不确定时倾向保留**：

| 02b 保留规则 | 含义 |
|---|---|
| ① 已知病毒 taxid 命中 | 保留 |
| ② 关键词抢救（phage/virus/capsid/terminase/integrase/prophage…） | 保留 |
| ③ 比对不可信抢救（length<50 或 pident<30 或 evalue>1e-5） | 保留（比对质量差，不足以据此排除） |
| ④ 全局 no-hit | **保留** |

**第 ④ 条是关键**：blastx 完全没命中的 contig 恰恰是**全新病毒**的来源。
对新病毒鉴定而言，no-hit 是最高价值的候选，绝不能当作"排除"。

v2 因此去掉"排除"档，改为 02b 口径的 `filter` / `strict` 双模式。

### L2 = 09b_Analysis_Verify（更严格的 CDD 过滤）

位置：`virome_pipeline.py:2244`「Part V: virus_validation（CDD 验证 + blast
身份 + 五层证据整合，由 9a 迁入）」。脚本 `validate_rescue_cdd.py`，
下游 `gen_final_judgement.py` → `final_judgement_table.tsv`、
`integrate_rescue_evidence.py` → `rescue_evidence_scored.tsv`。
产物目录 `09b_Analysis_Verify/virus_validation/`。

**严格在哪：多了「属/科核心域」交叉验证。** L1 只问"像不像病毒"，
L2 还问"**像不像它声称的那个属**"。

核心域表（`genera_core_aux_species_v3.tsv`）结构：
`core100` = 该属 100% 成员都有的域；`core90` = ≥90%；`aux` = 辅助域。

判定优先级（`validate_rescue_cdd.py:259-330`）：属在表 → 属级核心域；
属未命中、科在表 → 科级核心域兜底；都无 → PASS_VIRAL。

| EVIDENCE | 判据 | 处置 |
|---|---|---|
| `PASS_CORE` | T1 病毒域 + **属级**核心域命中 | 强证据，保留 |
| `PASS_CORE_FAM` | T1 + 仅**科级**核心域命中 | 强证据（科级），保留 |
| `PASS_VIRAL` | 有 T1，属/科核心均未命中 | 弱-中，保留但标注（可能片段） |
| `AMBIGUOUS` | 仅 T2 实证宿主蛋白 / T3 Root | 人工复核 |
| `REVIEW` | 有分类但无 T1/T2（延伸过头 / CDD 盲区） | 人工复核 |
| `NON_VIRAL` | 无白名单命中且无分类 | 疑似假阳性（宿主），建议去除 |

**v2 超家族归并（实现时必须带上，否则结果虚高）**：CDD 多标签效应使同一
家族多模型重复计数（**实测膨胀 ~6×**）；且跨界同源超家族（RT / 解旋酶 /
pol / HSP70）存在 viral 与宿主双版本模型，制造虚假外源域信号。解法：
`convertalis` 取 qstart/qend 核酸坐标 → 聚类成位点 → 按成员构成分类：

| 位点类型 | 含义 |
|---|---|
| `viral_only` | 仅病毒域 |
| `dual` | ext + 病毒域同位点 → 双重投影伪影 |
| `proximal_dual` | ext 紧邻病毒域（±300nt 同 frame）→ 区间错开伪影 |
| `confirmed_capture` | HSP70 家族位点（文献支持真捕获） |
| `pure_clean` | 干净的真实外源捕获候选 |

## 一、定位与边界

### 1.1 一句话定位

**识别组做「批量过滤」，注释组做「单条深挖」。** 共用同一套引擎与结果缓存，
差别只在**入口语义**和**结果视图**。

| | 识别组 · 候选序列验证（02b） | 注释组 · CDD / BLAST 卡片 |
|---|---|---|
| 问题 | 这批 contig 里哪些值得往下做？ | 这条已确认病毒的基因组有什么功能元件？ |
| 输入 | 整个 `contigs_` 运行的候选列表 | 单条 contig（可手输序列/文件） |
| 粒度 | 批量，一次跑完 | 逐条，按需 |
| 输出 | 过滤后 FASTA + `calls.tsv` 分类清单 | 命中表 + 结构域位置/边界 |
| 下游 | 决定哪些进入注释、聚类、提交 | 基因组图谱 / 引物 / GenBank 注释 |

### 1.2 接口

- 上游：`t-contigs`（组装结果再鉴定）的候选 contig 列表
- 下游：`/orf` → `/annotation` → `/genome`，及 `compare` 组 SDT 定种
- 平级：`/hostpredict` 宿主预测（交叉验证宿主类群）

## 二、入口：宿主分类选择 + 长度分流

**核心原则：本地快筛打头阵，NCBI 网络精算只对少量关键 contig。**
瓶颈：NCBI BLAST / CDD 走 URL API，单条数分钟，逐 contig 批量跑不可行。

### 2.1 宿主分类筛选（默认全部）

进入验证模块先选宿主类群，**默认"全部"**。选项来自
`databases/viral_prot/ictv_family_host.tsv`：

| 宿主来源 | 判读 |
|---|---|
| `plants` | 目标：植物病毒 |
| `fungi` | 真菌病毒污染（样品共生真菌） |
| `bacteria` | 噬菌体 |
| `invertebrates` | 可能来自传毒媒介昆虫 |
| `vertebrates` / `archaea` / 未知 | — |

筛选作用于候选集，便于聚焦植物病毒，或反向排查污染来源。

### 2.2 按长度分流

| 长度 | 归属 | 方法 | 库 |
|---|---|---|---|
| **≥ 1000 bp** | **病毒** | DIAMOND **blastx** + mmseqs2 **CDD**（可单选 / 双跑，结果取**并集或交集**） | `viral_prot.dmnd` / `cdd_db` |
| **250 – 1000 bp** | **类病毒** | **blastn** | `viroids-db/viroids_v4` |
| < 250 bp | 不处理 | — | — |

> **下限 250 bp 的依据**：类病毒全长 246–401 nt，低于 250 bp 的 contig
> 基本凑不出一条完整类病毒，比对结果无判别力（2026-09-08 用户确认）。
> **宿主归属唯一来源**：`run_dir/virus_classification.tsv`（工具④产物，8 级谱系）。
> 不引入 `organism_tax.tsv`（用户明确："完全不需要，不兜底没意义"）。
> 宿主筛选语义为「**含**」匹配（host.source 是复合值如 `algae+fungi+plants`，
> 选 plants 时该科保留）。

**为什么必须分流**：类病毒（viroid）全长仅 246–401 nt，**无蛋白编码能力**，
blastp / CDD 这类蛋白层方法对它们完全无效；反过来，用 blastn 查类病毒库
对 ≥1000 bp 的病毒 contig 也没有意义。按长度分流保证各自用对方法。

### 2.3 ≥1000 bp：病毒分支

**不预先做 ORF 预测**——两条主线都由工具自带翻译，直接吃核酸 contig
（2026-09-08 用户："不需要预测 orf，核酸就可以"）。

```
候选 contig（≥1000 bp，核酸）
   │
   ├─ A. DIAMOND blastx vs viral_prot（239MB 病毒蛋白库，自动 6-frame 翻译）
   │     ★ 不做科/宿主推断——宿主归属见 §2.2，来自 virus_classification.tsv
   │
   ├─ B. mmseqs2 translated search vs CDD（自动翻译，白名单 → 3-tier）
   │     viral / ambiguous / non_viral
   │
   ├─ C. HMM 三库（可选，默认关）→ 捕获远源病毒
   │     ⚠ 唯一需要蛋白输入的分支，若开启需先 ORF 预测
   │
   └─ 组合策略：A / B / A+B
        并集 = A 或 B 任一通过 → 保留（宽松，倾向保留）
        交集 = A 与 B 同时通过 → 保留（严格）
```

> ✅ **已定**：默认 **双跑 + 并集**，对齐 02b filter 口径的"倾向保留"。
> A / B 单独运行与交集模式仍作为可选项保留。
>
> 这与 02b 完全同构——`filter_virus.py` 同样是 `diamond blastx` +
> `mmseqs translated search`，全程不落 ORF 中间文件。

### 2.4 200–1000 bp：类病毒分支

```
候选 contig（200–1000 bp）
   │
   └─ blastn vs viroids_v4（9,353 条类病毒）
        ├─ 命中 → 查 viroids.taxonomy_info.tsv 取科 / 属 / 种
        └─ 未命中 → 进 unclassified（保留，仍可能是新类病毒）
```

类病毒库已下载就位，见 §3.5。

**判据（✅ 已确认 2026-09-08）**：类病毒序列短，覆盖度比 identity 更关键。

| 长度区间 | 阈值 |
|---|---|
| 300–1000 bp | identity ≥ 80% 且 覆盖 ≥ 60% |
| 250–300 bp | identity ≥ 80% 且 覆盖 ≥ 40%（短片段放宽） |

> 类病毒全长 246–401 nt，接近全长的 contig 覆盖度应接近 100%；
> 覆盖度低说明只比对上局部，需结合二级结构判定（后续可加）。
